# Contributing

Power Query functions and VBA modules for Australian month-end work. Everything lives as text so a reviewer can read your change in a diff. Ship the source as text, and use a workbook only to demonstrate it.

## Data boundary

Keep client data out. The `.gitignore` blocks `input/`, `output/`, `clients/`, `exports/` and the common export extensions, including `.aba`, `.myox`, `.ofx` and `.qif`. Fabricate any sample you need and keep it under `samples/`.

## Format rules

- Export VBA as text under `vba/`. The VBE expects CRLF on import, so `.gitattributes` marks `.bas`, `.cls` and `.frm` as `-text whitespace=cr-at-eol`, which keeps git from touching their line endings and stops a trailing CR being reported as a whitespace error. That means `git diff --check` will not flag a renormalised blob. `cargo run --locked --release --bin check-vba-encoding` checks this, and CI runs it.
- Keep Power Query M under `powerquery/` as plain text.
- Do not commit `.xlsm` or `.xlsx` as the source of truth for a function or module.

## Traps already found here

- `Csv.Document` infers width from the first row, so a one-field title row collapses the parse. Pass `Columns`, and put a caveat in a full-width trailing row.
- Typed M parameters such as `(x as date)` reject the shapes Excel hands over. Widen the type and use `Date.From(d, "en-AU")` so financial-year results stop following the machine locale.
- CSV formula injection: guard `=` in every case, and `+`, `-`, `@` only when the remainder is not a plain code. Otherwise account codes like `-00123` stop joining back to payroll. An A1-style reference such as `+A1` starts a formula, so an 'inert remainder' test has to be narrower than 'anything alphanumeric'.
- `IsNumeric(True)` returns `True` in VBA, so Booleans sum as -1. `Activate` on a hidden sheet activates the visible neighbour. `Scripting.Dictionary` runs on Windows Excel only.
- `Trim$` misses non-breaking spaces, tabs and CRLF in reconciliation keys.

## Local verification

Run these commands from `adapters/accounting-excel-toolkit/` in [Accounting Review Pipeline](https://github.com/ryanduguid/accounting-review-pipeline). Keep the root [Xero trial-balance contract](../../contracts/xero-trial-balance-v1/) as the data-only authority; do not vendor another copy into this adapter.

Rust checks the VBA source guard, account-transactions converter and aged review tools;
Python 3.14 or newer drives the retained suite.

```bash
cargo fmt --check
cargo clippy --locked --all-targets --all-features -- -D warnings
cargo test --locked --all-features
cargo run --locked --release --bin check-vba-encoding
python -B -m unittest discover -s tests -v
```

The frozen guard comparison needs CPython 3.15 and a checkout of
`e06647062efaf4410f7d4a414a0559ca51147267`. Python runs only that original
implementation; the production guard has no Python dependency. After
`cargo build --locked --bins --examples`, run:

```text
target/debug/examples/encoding-differential PATH_TO_PYTHON_3_15 PATH_TO_FROZEN_GUARD target/debug/check-vba-encoding 16
target/debug/examples/encoding-differential PATH_TO_PYTHON_3_15 PATH_TO_FROZEN_GUARD target/debug/check-vba-encoding 17
```

On Windows, use the `.exe` binary paths. Each seed compares generated byte
diagnostics and exact CLI exits/stdout/stderr. Native tests cover the original
20 test behaviours, offset truncation, installed-binary discovery and source
checking from an unrelated working directory. The guard uses only the standard
library; the converter uses the existing repository choices, `serde_json` and
`sha2`. The Cargo version follows the existing source-archive version, 0.1.8.

Use the same frozen checkout for the converter comparison:

```text
target/debug/examples/transactions-differential PATH_TO_PYTHON_3_15 PATH_TO_FROZEN_CONVERTER target/debug/xero-account-transactions 16
target/debug/examples/transactions-differential PATH_TO_PYTHON_3_15 PATH_TO_FROZEN_CONVERTER target/debug/xero-account-transactions 17
```

This checks amount scale, Unicode digits, dates, permissive CSV records,
inspection, mapping conversion and CLI behaviour. Successful CLI output bytes
are compared exactly, including platform newline translation. Invalid amount
diagnostics are compared as the same rejected text because the native tool uses
JSON quotation. Help, usage, JSON parser and OS error presentation can differ;
their CLI exits and stream selection are checked. Native tests cover all seven
previous converter tests plus formula refusals, mapping limits and raw-byte
identity. Run both comparisons on Windows and Linux.

The aged verifier, debtor evidence and replay comparison uses the same frozen
checkout's `tools/` directory and the directory containing all native binaries:

```text
target/debug/examples/aged-differential PATH_TO_PYTHON_3_15 PATH_TO_FROZEN_TOOLS target/debug 16
target/debug/examples/aged-differential PATH_TO_PYTHON_3_15 PATH_TO_FROZEN_TOOLS target/debug 17
```

It compares exact signed amounts, strict CSV parsing, timestamps, metadata,
ordered JSON, requests and briefing text. CLI comparisons check all 12 replay
cases and exact evidence bytes. Native tests cover the 31 original verifier,
debtor and replay test behaviours, with benchmark assertions retained in Python.
The benchmark imports the frozen Python reference only: its schema 1 Python
allocation measurements cannot represent a Rust process. Aged arithmetic uses
`num-bigint` and `num-traits`, already used by other native components in this
repository. These additions stay private to this crate.

On Windows with Windows PowerShell 5.1 or newer and desktop Excel installed,
run the checked-in acceptance checks in Excel itself:

```powershell
powershell -NoProfile -File tools/native_excel_acceptance.ps1
```

Use `-RepositoryRoot D:\src\accounting-excel-toolkit` to test a different
checkout. The runner requires Excel's Power Query engine and the
`Microsoft.Mashup.OleDb.1` provider. It exercises exactly 105 real-engine cases:
both fabricated Xero layouts, the fabricated Payday Super producer contract,
period and YTD selection, malformed exports, lazy evaluation, AU financial-year
boundaries, ABN validation, header promotion, fixed decimal ageing amounts,
missing ageing headers and separate supplier/expense-claim sections. Every
Power Query function is exercised.

The default `All` mode runs the 78 core checks and 27 Payday Super checks in
fresh child PowerShell and Excel processes. Within the Payday child, each of
21 queries reads only one of 20 fabricated files. This keeps Excel's
cross-source privacy/firewall composition state from masking adapter behaviour
while preserving the exact 105-check result contract. One check preserves a
quoted multiline field; 3 others materialise fabricated reports containing
500, 5,000 and 10,000 contribution
rows and print their measured refresh times.

The runner does not write to repository sources or samples. It creates its
workbook and adverse fixtures in a GUID-named system temporary directory,
closes the workbook, quits and releases every Excel COM reference in reverse
order, and removes the directory in its `finally` block.

VBA is not imported by automation because doing so depends on Excel's
machine-wide **Trust access to the VBA project object model** policy. Test VBA
in a disposable workbook by importing both `.bas` files, running
`ApplyWorkpaperHeader` against an entity name beginning with `=`, and running
`CompareKeyedRanges` against fabricated 2-column ranges with a leading-zero
key. Confirm the header is text rather than a formula, existing rows move down,
and `Recon Result` carries the expected difference. Do not weaken the Office
trust policy solely to run this check.

## Formula comparison cases

Import `modFormulaCompare.bas` into a disposable workbook without changing
Office trust settings. Use two fabricated workbooks and explicitly selected
equally shaped ranges. Record Excel version, module digest, range addresses,
source revisions and each observed result:

For an assert-based self-check, also import
`tests/native/modFormulaCompareTests.bas` and run `TestCompareFormulaRanges`.
It creates and closes its own fabricated workbooks without saving them, and
raises an error on a failed assertion. Retain the printed result and module
digests with the Excel version. This self-check has not yet been run in Excel.

| Before | After | Expected diagnostic |
|---|---|---|
| `=SUM(B2:B5)` | constant with the same displayed amount | `FORMULA_REMOVED` |
| `=SUM(B2:B5)` | `=SUM(B2:B4)` with an equal cached amount | `FORMULA_CHANGED` |
| constant | `=SUM(B2:B5)` | `FORMULA_ADDED` |
| identical `Formula2` text | identical text with changed formatting | no formula finding |
| no Excel workbook link | a new fabricated workbook link | workbook-level `EXTERNAL_LINK_ADDED` |

Also check that mismatched shapes and noncontiguous ranges are refused, source
cells and workbook links remain unchanged, and no source workbook is saved or
recalculated by the diagnostic. The Power Query runner does not import this module;
passing its tests cannot establish these VBA results.

## Pull requests

Say which function or module you changed and show the fixture that exercises it. For an M change, state the locale and column shape you tested against.

For a potential security vulnerability, follow [SECURITY.md](SECURITY.md) rather than opening an issue.
